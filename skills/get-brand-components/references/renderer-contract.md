# Generating collateral from a kit (the renderer)

**The primary way to turn a kit into an on-brand asset is the bundled renderer — do NOT hand-write per-asset CSS.** One engine composes any asset from any kit; the same content spec rendered through a different kit comes out fully on-brand for that brand (designed for dark, gradient, and light visual systems; verify the current output).

```bash
python3 <plugin-root>/skills/get-brand-components/scripts/render_kit.py --kit <slug|path> --spec <asset-spec.json> --out <out.html> \
        [--kit-dir <path>] [--theme light|dark] [--format doc|og|social-square|social-story|email|slide]
```

- `--kit-dir` renders a kit stored anywhere (kits don't have to live in `~/.octave/brands/`).
- `--theme` picks the light or dark palette when the kit carries both (`tokensDark`/`tokensLight`).

### Output formats

The same kit + spec can render to **multiple formats** — the brand kit is format-agnostic, so don't rebuild styling per format. `--format` sets the canvas: `doc` (default page), `og` (1200×630 share image), `social-square` (1080²), `social-story` (1080×1920), `email` (600px width), `slide` (1280×720 single-slide canvas — one hero-or-stats-sized spec per slide; for full decks use the deck skill). The *spec* controls content (a short hero/CTA spec makes a clean OG/social image).

**The OG share image is automatic at publish; every other variant is ask-first.** When an HTML deliverable is headed somewhere anyone with the link can open it — the asset-manager `public` tier, the microsite deploy, or the user saying at intake they'll publish, post, or share the link — render its share image without asking and place it beside the HTML:

```bash
python3 <plugin-root>/skills/get-brand-components/scripts/render_kit.py --kit <slug> --spec og-spec.json --format og --out og-frame.html
python3 <plugin-root>/skills/get-brand-components/scripts/render.py --file og-frame.html --out <deliverable-dir>/assets/og.png --width 1200 --height 630 --scale 1
```

The spec is one `hero` block carrying the deliverable's headline and a one-line subhead — write both fresh from the deliverable and hold them to editorial-rules.md; this copy renders on the social card. Delete `og-frame.html` after. Then confirm the deliverable's head references the image relatively (`assets/og.png`) with the block from [social-meta.md](../../shared/social-meta.md) — never an absolute URL, never a data URI. Square, story, and email variants stay opt-in: after producing the main asset, ask whether the user wants them, and only then render.

- **`skills/get-brand-components/scripts/render_kit.py`** — loads the kit, emits a self-contained HTML doc: `<style>` = `:root{}` from `manifest.render.tokens` + base64 `@font-face` from `manifest.render.fonts` + `skills/get-brand-components/assets/kit_base.css`; body = composed blocks; logo/icons inlined.
- **`skills/get-brand-components/assets/kit_base.css`** — brand-AGNOSTIC component stylesheet (every rule references a `--brand-*` token). This is the single source of truth for component CSS — fix a component once here and every asset for every brand inherits it.
- **Content spec** (JSON) — `{ title, blocks: [...] }`. Block types: `hero`, `stats`, `about`, `quote`, `section`, `features`, `comparison`, `checklist`, `cta`, `footer`, plus the imagery/marketing blocks:
  - **`split`** — image-paired feature row: `{kicker, heading, paras[], bullets[], image, imageSide: left|right, cta}`. The `image` is a kit-relative path (inlined) or URL; it's framed (rounded + shadow).
  - **`logos`** — logo wall: `{label, mono: bool, items:[{img}|{text}]}`. `mono` greyscales color logos for a uniform wall.
  - **`pricing`** — plan cards: `{plans:[{name, price, period, blurb, cta, features[], featured, badge}]}`; the `featured` plan gets the primary border + badge.
  - Any content block can take `surface: "dark"` to render as a full-bleed dark band (e.g. a logo wall with white logos).
  - Emphasis: wrap a word in `**double asterisks**`. `hero.featured.logoKit` pulls *another* kit's logo (customer logo in a vendor case study).
- **Real imagery** — store the brand's actual product screenshots / customer logos in the kit's **`images/`** dir (downloaded during the walk) and reference them by relative path; the renderer inlines them as data-URIs (self-contained). Don't fake imagery with gradient placeholders when the real assets exist on the site — extract logo walls and a hero/product shot. (Apply the same logo-verification care: confirm a "customer logo" is real, not a stray asset.) Optional `--brand-texture` token layers a subtle pattern (dot/grid) onto dark bands.
- **Visual constraints** — respect `manifest.rules` and `corrections.md` when styling the asset.
- **After rendering** — run `skills/get-brand-components/scripts/check_adherence.py` on the output, then the [fidelity gate](fidelity-gate.md) if the asset is shippable.

### Imagery is earned, not defaulted

Place a kit's screenshots and logos only where they **truthfully illustrate the specific point** — never because the kit happens to have them. A product shot dropped into a `split` whose copy describes something the screenshot doesn't show, or a logo wall stamped onto every doc (including internal ones like battlecards), reads as filler and undercuts the asset.

- **Screenshots:** use one only when the section is genuinely *about* what it shows, and caption it for what it actually is (e.g. "The Octave platform"), not for the narrative you wish it depicted. If no apt image exists, carry the point with type + icon tiles — don't shoehorn.
- **Proof:** prefer a **specific, true** callout (a named reference customer matching the audience, with the real result) over a generic logo grid. One earned proof beats a wall of logos.
- **Don't destroy brand:** `mono` greyscale / hard inversion can erase a logo's identity — only use it when a uniform wall genuinely serves the layout.
- **Never** use gradient/masonry placeholder tiles as stand-in "content."

The test for every image: *does it make this exact point clearer, or is it decoration the kit made available?* If the latter, cut it. (The earlier "Real imagery" note means *don't fake* imagery with placeholders — it does **not** mean force every real asset into every doc.)

### The `manifest.render` token contract

For a kit to be renderable it needs a `render` block in `manifest.json`:
- `hasDarkBand` (bool — dark hero/footer/CTA vs light), `docWidth`, `heroVisual` (`chips`|`masonry`|`image`|`none`), `heroImage` (kit-relative png/jpg/webp/svg shown behind the hero copy when `heroVisual` is `image`, with `--brand-hero-scrim` as the legibility layer), `webfonts` (optional `<link>` URL for fallback faces)
- `fonts`: `[{family, weight, style?, file, format}]` — base64-embedded so output renders the real face; `format` is `woff2`, `woff`, `truetype`/`ttf` or `opentype`/`otf`
- `logo`: `{onDark, onLight, onDarkSource, onLightSource, lockup}` — per-surface logos. **The renderer picks `onDark` on dark surfaces and `onLight` on light ones** (this is what prevents white-logo-on-white-footer). `onDarkSource` / `onLightSource` record the URL each variant was downloaded from (provenance, so a wrong asset can be audited); a source in a `customers|partners|trusted|clients|logos` container or a foreign domain is suspect. `lockup` = `{mark, wordmark, wordmarkWeight}` for brands whose logo is a mark + wordmark; `mark` (or `markImg` for a raster mark) is a kit-relative file, never a URL, and the renderer inlines it like any other asset. **Both variants must be pixel-verified (see the logo source rule + wordmark gate in Step 2.5) before the kit is considered complete.**
- `tokens`: the `--brand-*` contract — colors (`bg`, `canvas`, `surface`, `surface-dark`, `ink`, `muted`, `faint`, `on-dark`, `primary`/`-ink`, `link`, `border`, `negative`, `band`, `glow`, `tile-bg`/`-ink`/`-glow`, `grad-border`), emphasis (`emph-ink-light`/`-dark`, `emph-underline`, `emph-weight`), type (`font-heading`/`-body`, `weight-*`, `tracking-heading`, `h1`/`h2`), shape (`radius-section`/`-pill`, `shadow`, `btn-shadow`), and the **foundations** (`shadow-sm`/`-md`/`-xl` elevation, `ease`/`duration` motion, `icon-stroke`, gray ramp, semantic states, spacing scale, gradients — see Step 4). `hero-bg`/`cta-bg` add a light-surface wash; `heading-transform` forces all-caps.
- Surfaces and components: `ink` is the text color on `bg`, the document surface, and `on-dark` is text on bands. A dark-only brand sets a dark `bg`, a light `ink` and `defaultTheme: dark`; there is no light theme to invent, and the pre-gate's contrast check catches ink that cannot be read on bg. `stat-weight` / `stat-ink` style stat numerals (fallbacks: the heading weight, the inherited color). `card-bg` / `card-border` / `card-highlight` give feature and plan cards their fill, border and a 1px lit top edge; a translucent glass card is `card-bg: rgba(255,255,255,.04)`, `card-border: rgba(255,255,255,.1)`, `card-highlight: linear-gradient(90deg, transparent, rgba(255,255,255,.35), transparent)`. `plan-featured-border` colors the highlighted pricing plan's border (fallback `primary`; a white-button brand sets its accent here). `pos-ink` colors checklist ticks and positive marks (fallback `positive`, then `primary`). `measure` caps body copy (default `68ch`). The comparison table measures its cells, markers and header from `--cmp-pad`, `--cmp-mark` and `--cmp-gap` set on the table, so the header label always starts over the row text.
- Emphasis, full set: `emph-ink-light` / `emph-ink-dark` (word color per surface, `inherit` when color is not the device), `emph-weight`, `emph-font` (a different face for the word), `emph-style`, `emph-underline` / `emph-underline-dark` (a gradient bar or `none`), the highlighter chip `emph-bg` / `emph-bg-dark` / `emph-radius` / `emph-pad`, and gradient text `emph-gradient` + `emph-clip: text` + `emph-fill: transparent` + `emph-bg-size: 100% 100%` + `emph-bg-pos: 0 0`.
- Labels and secondary text: `font-label` / `tracking-label` / `label-transform` (eyebrows and kickers), `faint` (secondary text ON dark bands; defaults to a 68 percent white tint), `border-dark` (hairlines on dark bands), `body-ink` (body copy; defaults to `ink`), `primary-hover`.
- Buttons: the resting primary button reads `btn-bg` / `btn-ink` / `btn-border` / `btn-hover-bg` / `btn-hover-ink` / `btn-weight`, falling back to `primary` / `primary-ink` / transparent / `primary-hover` / 600. Eyebrows, stat units, quote marks and badges keep using `primary`, so an outline-button brand sets `btn-bg: transparent` and `btn-border: <ink>` without recoloring the rest. On dark bands the `-dark` variants apply (`btn-bg-dark`, `btn-ink-dark`, `btn-border-dark`, `btn-hover-bg-dark`, `btn-hover-ink-dark`), each falling back to its base token, so an outline brand that inverts (ink outline on light, white outline on dark) sets both sets and a filled brand sets none.
- Heading weights: `weight-h1` (hero) and `weight-h2` (section, CTA and split headings) override `weight-heading` where the site uses different weights.
- Radii: every component radius chains to `radius` (`border-radius: var(--brand-radius-card, var(--brand-radius, 16px))`), so `--brand-radius: 0` squares the whole kit; `radius-card` (cards, tables, quote, dark footer), `radius-tile` (icon tiles), `radius-chip`, `radius-quote` and `radius-badge` refine per role.
- The focus-ring fallback is `0 0 0 3px var(--brand-primary)`; `kit_base.css` carries no off-palette color literal, so `skills/get-brand-components/scripts/check_adherence.py --file <out.html> --kit-dir <kit>` runs clean on a kit that uses only its tokens.
- Depth lives in one place: `glow` and `texture` paint the hero only. Every other dark surface is the solid `band` unless the kit opts that surface in with its own layer token: `cta-glow` / `cta-texture`, `band-glow` (section bands), `footer-glow`. A glow repeated on every band reads as blotches, which is the commonest generated-page tell on dark brands; keep grid textures at or below 5 percent alpha and grain at 10 to 14 percent. Layering rule the stylesheet relies on: `glow`, `texture`, `hero-texture` and the `*-glow` tokens are image layers and default to `none`; a color in a non-final `background` layer invalidates the whole declaration, which is why the stylesheet never falls back to `transparent` there.
- `gallery` (optional, consumed by `skills/get-brand-components/scripts/render_gallery.py`): `{"surfaces": {"hero"|"stats"|"quote"|"cta"|"footer"|"comparison": "dark"|"light"}, "headingAlign": "center"|"left", "cardStyle": "hairline"|"shadow"|"flat", "navStyle": "bar"|"floating", "sectionFrame": "none"|"hairline", "eyebrow": true|false, "secondaryCta": true|false, "emphasis": true|false, "eyebrowStyle": "plain"|"chip", "arrow": true|false, "statsStyle": "strip"|"inset"}`. `eyebrowStyle: chip` draws the hero eyebrow and section kickers as hairline pills; `arrow: true` (or `render.buttonArrow`) adds the trailing arrow to primary buttons, and only then, because the arrow is a device the brand either uses or does not; `statsStyle: inset` floats the dark stat strip as a rounded card on the page gutter; `emphasis: false` keeps the fixed copy but strips its emphasized word. Feature tiles take the first icons from `icons.json` when the spec names none, so a kit with icons never shows empty tiles. The fixed gallery copy reads as a plain product page, never as a description of itself. `render.surfaces` (same keys as `gallery.surfaces`) applies to every consumer render, not only the gallery. `eyebrow: false` removes the eyebrow and section kickers for brands that never use small labels above headings; `secondaryCta: true` renders the brand's secondary button beside the primary; `emphasis: false` keeps the fixed copy but strips its emphasized word, for brands with no highlight device; `eyebrowStyle: chip` draws the eyebrow as a hairline pill; `arrow: true` (or `render.buttonArrow`) adds the trailing arrow to primary buttons, and only then, because the arrow is a device the brand either uses or does not; `statsStyle: inset` floats the dark stat strip as a rounded card on the page gutter. Feature tiles take the first icons from `icons.json` when the spec names none, so a kit with icons never shows empty tiles. The fixed gallery copy reads as a plain product page, never as a description of itself. The gallery's reference strip shows both logo variants, `onLight` on white and `onDark` on `--brand-bg`. Dark surfaces default to the band (`--brand-texture`, `--brand-glow`, `--brand-band`); a brand whose band belongs only to the hero and closing CTA sets `--brand-quote-bg`, `--brand-footer-bg` and `--brand-section-bg` (with optional `--brand-quote-border` / `--brand-footer-border`) to its card surface. A dark-ink kit whose site closes on a light band or a white footer sets `surfaces.cta: light` / `surfaces.footer: light` with `--brand-cta-bg` (a color or gradient), `--brand-cta-ink`, `--brand-cta-muted`, `--brand-cta-btn-bg` / `-ink` / `-hover-bg`, and `--brand-footer-light-bg`, `--brand-footer-light-ink`, `--brand-footer-light-border`; the footer then picks the `onLight` logo. `heroEyebrow: false` drops the eyebrow from the hero only, for brands that label sections but not the hero. On a `defaultTheme: dark` kit a dark content band is the same surface as the sheet, so it renders `flush` (no padding of its own). A kit may also carry `hero.html`, one self-contained `<section class="hero-bespoke">` styled only with `--brand-*` tokens, which replaces the mechanical hero in the gallery.
- `surfaces` (optional): `{"cta"|"footer"|"quote"|...: "dark"|"light"}`, the brand's surface per block type for EVERY asset `render_kit.py` composes (the one-pager and collateral, not only the gallery). A block's own `surface` wins; without the map the `hasDarkBand` default applies. Set it to the same values as `gallery.surfaces` when the brand closes on a light CTA or a white footer. `eyebrowStyle: chip` also styles section and split kickers. `render.eyebrow` / `render.heroEyebrow` (falling back to the `gallery` values) drop eyebrows and kickers from every asset `render_kit.py` composes, so a brand without small labels never gets them on a one-pager. A closing band that runs full-bleed with its glow fading into the footer sets `--brand-cta-margin: 40px 0 0`, `--brand-cta-radius: 0` and `--brand-cta-footer-gap: 0` (unset: the inset card with a 40px gap); `--brand-cta-pad` sets its padding. `--brand-cmp-width` (default 760px; `none` = full gutter width) sizes the comparison table, and `--brand-flush-gap` (default 34px) is the gap between consecutive dark bands on a dark sheet; set it to the `.wrap` padding (44px) for an even band rhythm. `--brand-label-size` sets the small label text (stat labels, quote byline, comparison headers; defaults 12 / 12.5 / 11.5px). `--brand-quote-border` and `--brand-footer-border` are full `border` shorthands (`1px solid #3e3955`); a bare color draws nothing.
- `tokensDark` / `tokensLight` (optional): override maps for the opposite theme, merged when `--theme` is passed.
- `defaultTheme` (optional): `light` | `dark`.

Add `render` when building a kit (Step 6). The verbose `tokens.css` + `components.html` remain the human-readable reference; `render` is the machine contract the engine consumes.

### Fallback (manual compose)
If a one-off needs a layout the block types don't cover, you can still inline `tokens.css` + `skills/get-brand-components/assets/kit_base.css` and write markup using the `kit_base` classes — but prefer adding a block type to the renderer over hand-CSS, so the fix compounds.

Reference token names are brand-agnostic, so the same spec restyles to any captured brand just by swapping `--kit`.


Read the structured-link contract in [task-method.md](task-method.md). Use explicit text items or {label,href,target?}; all interactive blocks preserve destinations. Missing href is an authoring error. Capture OG at --width 1200 --height 630 --scale 1 --no-full-page.

Lockup marks preserve the complete verified SVG. Store approved surface variants for recoloring; the renderer does not reduce a logo to its first path or invent a new color treatment.
