# Per-deal brief spec

The hosted asset a watched deal keeps updated. It is an **internal, seller-facing** document: one deal, one page, current answer first. It is NOT a dossier (that's `/octave:research`), NOT a coaching microsite (that's `/octave:deal-coach`) — it is the standing answer to "what's my move here, and what changed."

## Format and styling

- Single self-contained HTML file per deal. Follow [../../shared/formats/html-document.md](../../shared/formats/html-document.md) and [../../shared/presentation-principles.md](../../shared/presentation-principles.md).
- **Workspace company's brand**, resolved the same way deal-coach does it: `get_workspace_company` → cached kit at `~/.octave/brands/<slug>/` (inline `tokens.css` + `kit_base.css`, verify the logo is genuinely the workspace company's mark before embedding) → build via `get-brand-components` (up to 3 attempts) → generic preset last. The target account is named in content, never in the design system.
- Internal deep-links (`app.octavehq.com/entity/...`, recording URLs with timestamps) are correct here — this asset is for the seller.
- Local working copy: `~/.octave-nba/briefs/<workspace>/<account-kebab>/index.html`. Published via the asset-manager route; default privacy `workspace`; vanity slug `nba-<account-kebab>`; the asset id is recorded in the state file so updates hit the same URL every time.

## Sections, in order, with density caps

### 1. Header
Account + deal name, amount / stage / close date (or the explicit "not in CRM" gap marker), deal owner, `Updated <date>` — and the **position statement**: the one sentence from action-derivation § 1. The position statement is the title-adjacent element a manager reads in three seconds.

### 2. Do this now
The ranked actions (max 3), each rendered as a card with its four parts: move (heading), why now (evidence with quote + jump-to-moment link), strategy source (plain language), execution hook (what to run or send). Carried actions show their `since <date>` badge. ≤ 120 words per card. If the run produced zero actions, this section says so plainly and names the trigger being watched for — an empty-but-honest state, never filler.

### 3. What changed
Delta list since the previous update: new evidence (calls, emails, findings), retired actions (with the closing evidence — give the rep the win), new intel (library changes, segment items) that fed the actions. First publish: omit the section entirely. Nothing changed: the brief wasn't updated at all (stability rule), so this section never says "nothing changed."

### 4. Position detail
Compact reference, table-first: methodology stage vs CRM stage (the two-axis read), buying-committee coverage vs prescribed personas (who's engaged, who's missing), competitive posture (who's in the deal, counter status), momentum vs the workspace's stage benchmark. Every cell traces to a tool result; unknowns render as "not observed," never as invented values.

### 5. Footer
Evidence lanes used this run (calls / emails / CRM / caller-supplied), counts (events, findings, quotes), window covered, `Generated by /octave:next-best-action` + timestamp.

## Whole-brief caps

- ≤ 2 screens at desktop width; the rep reads it between meetings, not at a retreat.
- Max 3 action cards, max 8 rows in Position detail, max 6 items in What changed.
- No section invents content to look full. Thin evidence → thin brief + an honest footer.

## Update discipline

- Same asset, updated in place (upload scripts replace files; `asset_update` for metadata) — the URL a rep bookmarked keeps working.
- **Stability rule** (from SKILL.md Step 6): no new evidence + no action change → no upload. Re-worded sameness is churn, and churn teaches reps to ignore the brief.
- Review policy per SKILL.md Step 6: full review gate on first publish; lint + orchestrator groundedness on sweep updates; full gate again on structural change or every 10th update.
