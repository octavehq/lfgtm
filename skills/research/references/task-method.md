# research: task method

### Resolve the task and evidence
For workspace-backed research, read [gtm-context.md](../../shared/gtm-context.md) and resolve the seller offering, commercial motion, audience, and applicable playbook/cells. Read [evidence-and-inputs.md](../../shared/evidence-and-inputs.md) for source handling and operator input; read [output-readiness.md](../../shared/output-readiness.md) before delivery. Load the HTML review/brand references only for HTML output. Load [analytics-contract.md](../../shared/analytics-contract.md) only when calculating trends, cohorts, or comparative rates.

Infer occasion and format from the request; text remains the default. Retrieve the target's relevant CRM records and calls before asking for known context. Resolve a specific opportunity for deal work. Ask grouped questions only for details that change the requested prep, such as the decision sought, unrecorded commitments, or missing account outcome measurements. Continue supported work while awaiting answers, then incorporate them with provenance and validate the revised result.

Read full selected offering, use-case, capability/prerequisite, persona, and proof records before deriving demo steps or claims. A slim inventory finds candidates; it does not establish a feature or result. Record why the selected proof fits this offering and buyer. When a cell is absent, describe the nearest context's relevant similarities and mismatches qualitatively; mark the resulting positioning provisional.

Generate one content model before selecting its renderer: objective, relevant account facts, confirmed needs, hypotheses to test, buyer-specific argument, applicable proof, questions, next decision, and remaining operator inputs. Text and HTML must preserve the same claims, uncertainty, and recommendations. Review factual fidelity, commercial fit, and requested scope for both; add visual review for HTML.

Read [occasion-workflows.md](occasion-workflows.md) for the applicable mode.
