### One content contract across engines
For workspace-backed content, read [gtm-context.md](../../shared/gtm-context.md). Read [evidence-and-inputs.md](../../shared/evidence-and-inputs.md) when using factual personalization, proof, or missing operator input, and [output-readiness.md](../../shared/output-readiness.md) before presenting copy. Load [content-contracts.md](content-contracts.md) for the selected channel. Load HTML review rules only for an explicitly requested HTML artifact.

Resolve offering across product/service/solution, relevant feature/use case, audience/persona and segment, motion, custom playbook, relationship stage, language, customer voice/writing style, intended CTA, and requested count. Retrieve CRM/calls for prior touches and commitments before asking for missing context. Ask a grouped question only for unresolved inputs affecting the copy; continue the supported draft, then incorporate replies and validate the result. Keep any agreed planning placeholder visible and separate from finished copy.

Build an inspectable content packet containing the selected argument, supported capability, relevant proof, buyer context, prior-used angles, constraints/prohibited claims, and source/provenance. Read full selected entities; slim rows are discovery only. Pass the same task packet to the chosen engine through supported fields. Inspect a saved agent's available configuration for offering, audience, channel, and constraints; do not assume an agent name proves compatibility. If configuration is inaccessible, state that limit and ask only if it creates material ambiguity. Never imply unsupported runtime overrides succeeded.

Validate every returned result independently of its engine: right offering/buyer/motion, prior-context fidelity, exact count/channel, customer language, proof applicability, no unjustified promise, and a suitable next step. Repair violations before handing through generated content. Present copyable payloads separately from source notes and unresolved decisions.
