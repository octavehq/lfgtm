# qual-doctor: task method

Discover the supported Octave tools and call verify_connection; confirm the exact workspace before reading or tuning. Read the selected saved agent's actual configuration and linked entity IDs. Resolve product/service/solution/core-feature and Motion-related sections through their supported schemas/APIs; do not send a Motion ICP to a generic update_entity call unless the active tool contract explicitly supports it.

Establish the intended motion and fit definition from library, CRM outcomes and calls, then resolve operator disagreements through targeted questions. Competitor usage may support displacement fit, be neutral, or reduce near-term opportunity because of an evidenced constraint. Evaluate timing, switching barriers and replacement value; do not encode incumbent usage as a universal BAD rule.

Separate observed tool output from diagnosis. Record selected entity, actual section score, returned answers, confidence, sources and configuration version. Display candidate scores only when the tool returns their trace. Without traces, label routing cause as a hypothesis and use controlled forced-entity versus routed runs only where supported; otherwise state the diagnostic limit. Never invent exact point effects without the actual scoring formula and inputs.

For each decisive question record evidenceState: verified_yes, verified_no, unverified, conflicting, or unavailable; retain the raw tool answer separately. Missing public evidence is not verified No. If the backend exposes only Yes/No, do not fabricate an UNKNOWN API value or silently rewrite the returned answer. Flag the observability/scoring limitation and redesign the criterion or use a supported unknown policy. An instant exclusion requires affirmative evidence for the actual exclusion condition with correct polarity. Public-data executions need publicly observable questions/proxies; internal-only criteria require authorized accessible evidence.

Create a labeled diagnostic set and a separate held-out set before tuning. Include good, bad, borderline, unknown-evidence and adjacent persona/segment cases relevant to the motion. Labels require rationale from known outcomes/operator judgment; distinguish fit from buying readiness. With a small sample, call the result exploratory and collect additional cases before claiming general calibration.

Measure routed entity accuracy, section-score separation, false positives/negatives at declared thresholds, unknown-evidence rate and subgroup regressions. Repeat selected cases when research/output variance may change the conclusion. State one causal hypothesis per tuning round where feasible. Inspect every agent sharing the edited entity; snapshot current questions/descriptions/configuration and protected neighbors. Use a clone/sandbox when supported, otherwise disclose shared impact. Apply the authorized scoped change, read back the exact fields, then run diagnostic plus held-out and affected-agent checks. Report actual observed changes, regressions and remaining uncertainty. Stop/recover if protected fields or unrelated agent behavior changes unexpectedly.
