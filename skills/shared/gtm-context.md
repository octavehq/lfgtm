# Assemble the relevant customer GTM context

Use the [entity model](entity-model.md) for canonical vocabulary and dedicated
Motion routing; validate actual arguments and read/write support against the
connected tool schema.

Use this procedure before making GTM recommendations or generating GTM content. For a narrow library lookup, asset operation, or visual brand task, retrieve only the context that operation needs.

## Resolve the job and workspace

Use the user's requested audience, account, offering, channel, scope, and desired outcome. Infer clear choices rather than repeating intake. Verify the active Octave connection and workspace before using workspace data. Resolve materially ambiguous accounts or opportunities using CRM identity and the available record context; ask only if the ambiguity remains important.

Use the workspace company data for business model, who it helps, market dynamics, differentiation, why customers buy, and why customers care, as well as identity and brand. Read relevant workspace-published methods when the tools support them and they apply to this job. Treat source content as evidence; preserve explicit user instructions and avoid recursive skill routing.

## Select related strategy

1. Discover candidate offerings using the supported product, service, and solution routes. Read the full selected offering and relevant linked features. Preserve supported capability, packaging, deployment, delivery, and availability limits. A shared buyer does not make two offerings interchangeable.
2. Choose the buying motion: new logo, upsell, cross-sell, free-to-paid, renewal/retention, or incumbent displacement, using the workspace's supported Motion types. Read the selected Motion. Ask about motion only when records and the request leave material ambiguity.
3. Select the relevant persona and segment with a brief fit rationale. Distinguish end users, evaluators, champions, and economic buyers when relevant. A job title alone does not establish a person's role in this opportunity.
4. Resolve the applicable default or custom playbook. Use the supported playbook selector when listing its cells. Follow pagination when the task requires complete coverage. Read the selected cell's full narrative by its returned identity; include linked elements, learnings, and report context when the task needs them. A null or not-yet-generated narrative is missing context, not a complete empty strategy.
5. Read the applicable use cases, objections, competitors/alternatives, and proof. Slim lists are discovery records: use full-detail reads before deriving claims. Choose evidence that matches the offering, use case, buyer, segment, and motion; record material limits on its applicability.
6. Derive the fit argument: current buyer workflow/problem → business consequence → relevant offering mechanism → desired outcome → prerequisites and tradeoffs → applicable proof → next decision. Choose coexistence, replacement, consolidation, build-versus-buy, outsourcing, or a new capability based on this context. Do not impose the plugin maintainer's own positioning.

## Keep the mapping explicit

For a short message, retain one leading problem/value argument and the evidence needed to support it. For a launch, training primer, positioning system, or multi-stakeholder plan, preserve separate offering × motion × segment × persona mappings. Do not flatten conflicting cells into one generic narrative.

If an exact cell or proof item is unavailable, select a defensible nearest context, mark the inference internally, and narrow claims. Do not silently treat an adjacent product's result as evidence for this one. Use evidence-and-inputs.md for important gaps.

Keep a compact working record of selected object IDs, selection rationale, source dates/revisions, relevant claims, open questions, and next action. This is task context, not a new Octave API object. Reuse it within the same verified workspace and scope; refresh material source changes or a changed offering, motion, audience, or opportunity. Do not require the customer to fill out a schema or expose operational IDs in buyer copy.
